# Level-raft experiment

The controls edit SI model parameters. Cargo starts at 100 kg in all three challenges; unit switching only changes presentation (1 lb = 0.45359237 kg). Log count is an integer 1–12; diameter 10–100 cm; mass overrides 0.1–1000 kg; cargo 0–1000 kg. Diameter resets the selected log to wood density 600 kg/m³. Log length remains 0.7957747 m. All log tops align with a constrained level deck. There is no roll/trim model.

For each horizontal cylinder, submerged cross-sectional area is computed from the exact circular-segment formula. A bisection solves total displaced fresh-water mass = timber mass + cargo mass. Overloaded designs have no floating equilibrium. The preview uses this equilibrium immediately. Release integrates vertical acceleration using gravity, Archimedes buoyancy and approximate linear/quadratic drag with RK4 at 240 Hz. Sixteen simulated seconds play in three seconds. Drag is illustrative, not experimentally calibrated. Deck, lashings and cargo displacement are omitted. Volume reserve is distinct from vertical clearance.

Research: [OpenStax Archimedes principle](https://openstax.org/books/university-physics-volume-1/pages/14-4-archimedes-principle-and-buoyancy). Library options reviewed: [Rapier force API](https://rapier.rs/docs/user_guides/javascript/rigid_body_forces_and_impulses/), [Three.js GPU water example](https://threejs.org/examples/webgpu_compute_water.html), [PhET buoyancy](https://phet.colorado.edu/en/simulations/buoyancy). Rapier supplies rigid-body dynamics but would still require displaced-volume forces. The Three.js example is water rendering/interaction, not a drop-in validated raft model. No external physics library was added; the explicit hydrostatic solver is independently checked against numerical area integration and the motion integrator against a smaller timestep.

The error-correction visualization shows one editable example separately from the exact binomial decoded-error probability. Tapping received copies changes that example, not the assumed independent corruption probability or challenge score. Bit changes are data corruption, not coin tosses. Repetition can recover a minority of corrupted copies; correlated errors are outside the model.
